# 🧠 MCP Client  
### Async Orchestration Layer for Model Context Protocol (MCP)

The MCP Client is the intelligent orchestration layer of the MCP architecture.  
It connects a Large Language Model (LLM) with one or more MCP Servers and manages tool execution, response generation, and conversation flow.

This repository contains the backend logic that powers tool-aware AI responses.

---

# 🏗️ System Architecture

The MCP Client sits between the API/Frontend layer and the MCP Servers.

```

User (Frontend / FastAPI)
↓
MCP Client
↓
┌───────────────┬───────────────┐
│ Desktop Server│ Expense Server│
└───────────────┴───────────────┘

````

The client does NOT execute tools itself.  
Instead, it coordinates tool execution across connected MCP servers.

---

# 🎯 Core Responsibilities

The MCP Client:

- Connects to multiple MCP servers via stdio transport
- Retrieves available tools dynamically
- Binds tools to the LLM
- Detects tool calls generated by the LLM
- Executes the correct tool on the correct server
- Sends tool results back to the LLM
- Produces the final human-readable response

---

# ⚡ Execution Flow

1. Receive user message (via FastAPI or direct call).
2. Initialize `MultiServerMCPClient`.
3. Fetch available tools from connected servers.
4. Bind tools to LLM (`ChatOpenAI`).
5. Invoke LLM with user prompt.
6. If tool call is detected:
   - Extract tool name and arguments.
   - Execute tool asynchronously.
   - Wrap tool result using `ToolMessage`.
   - Re-invoke LLM with tool result.
7. Return final AI response.

---

# 🧩 Multi-Server Support

The MCP Client supports connecting to multiple servers simultaneously.

Example configuration:

```python
servers = {
    "expense": {
        "transport": "stdio",
        "command": "fastmcp",
        "args": ["run", "server.py", "--no-banner"]
    },
    "desktop": {
        "transport": "stdio",
        "command": "fastmcp",
        "args": ["run", "desktop_server.py", "--no-banner"]
    }
}
````

This allows the LLM to intelligently choose tools across different domains.

# 🧠 Async Design

The client is fully asynchronous.

```python
async def model(prompt):
```

Benefits:

* Non-blocking tool execution
* Efficient I/O handling
* Ready for concurrent requests
* Production scalable
